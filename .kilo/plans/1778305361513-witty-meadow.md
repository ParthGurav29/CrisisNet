# CrisisNet BLE Mesh Networking Bug Analysis & Fix Plan

## Executive Summary

After reading the entire codebase, I identified **5 critical root causes** for discovery and messaging failures. The primary issues are:

1. **Dual-connection collision** - Both devices try to become BLE Central simultaneously
2. **Concurrent writeCharacteristic calls** - BLE only allows ONE in-flight write
3. **Session establishment timing** - `linkReady` not properly gated before sending
4. **Missing deterministic initiator election** - No tie-breaker for connection roles
5. **Peer state tracking mismatch** - UI store doesn't sync with mesh layer state

## STEP 3: Root Cause Analysis

### A) Discovery Failures

#### Bug 1: Dual-Connection Collision (CRITICAL)
**Location:** `src/mesh/meshService.js:646-658`

**Problem:** When two devices discover each other, BOTH try to connect as BLE Central. No deterministic initiator election.

```javascript
// Current code - sends to ALL peers without checking who initiated
const readyPeers = [];
for (const [peerId, peer] of this.peers.entries()) {
  const state = this._getPeerState(peerId);
  if (state.sessionEstablished && state.peerRegistered) {
    readyPeers.push(peerId);  // ← No check if we're the connection initiator
  }
}
```

**Impact:** Connection failures, immediate peer loss, discovery never stabilizes.

#### Bug 2: LinkReady Not Gated Properly
**Location:** `src/mesh/core/PeerRegistry.js:44`

**Problem:** `linkReady` is set to `true` on discovery, but `sendMessage()` in meshService only checks `sessionEstablished && peerRegistered`.

```javascript
// PeerRegistry.js line 44
linkReady: true,  // Set on discovery, but never used to gate sends

// meshService.js line 648 - WRONG: doesn't check linkReady
if (state.sessionEstablished && state.peerRegistered) {
  readyPeers.push(peerId);
}
```

#### Bug 3: Missing Connection Initiator Tracking
**Location:** `src/mesh/meshService.js:287-311`

**Problem:** No tracking of which device initiated the GATT connection. Both devices think they're the server.

---

### B) Messaging Failures

#### Bug 4: Concurrent WriteCharacteristic Calls (CRITICAL)
**Location:** `src/mesh/meshService.js:666-679`

**Problem:** BLE only allows ONE in-flight write per connection. The code uses `Promise.all()` to send to all ready peers simultaneously.

```javascript
// BUG: Parallel writes cause BLE to drop connections
const sendOps = [];
for (const peerId of readyPeers) {
  sendOps.push(
    this.protocol.sendMessage({ recipient: peerId, content, priority })
    // ↑ All these execute concurrently - BLE will reject!
  );
}
await Promise.all(sendOps);  // ← CRITICAL BUG
```

**Impact:** Messages fail silently, "message_failed" events fire, no delivery confirmation.

#### Bug 5: Session Establishment Not Awaited
**Location:** `src/mesh/meshService.js:310`

**Problem:** `_establishSessionForPeer()` is called but not awaited, so the peer may not be ready when `sendMessage()` is called.

```javascript
peerRegistry.updatePeer(peerId, rssi, ...);
// ...
this._establishSessionForPeer(peerId);  // ← Not awaited!
// ...
emit('peer_discovered');  // UI shows peer immediately, but session may not be ready
```

---

### C) Dual-Connection Collision

#### Bug 6: No Deterministic Initiator Election
**Location:** Entire meshService.js architecture

**Problem:** Both devices are symmetric (advertise + scan + GATT). No logic to decide who should be Central vs Peripheral.

**Solution needed:** Use Node ID comparison to deterministically assign roles:
- Lower Node ID = Central (initiator)
- Higher Node ID = Peripheral (advertiser)

## STEP 4: Fixes

### Fix 1: meshService.js - Add Connection Initiator Election & Sequential Sends

**File:** `src/mesh/meshService.js`

**Change 1a: Add initiator election and connection state tracking (after line 114)**

```javascript
// Add after _getPeerState() method (around line 114)
_getConnectionRole(peerId) {
  const myId = this.userId || '';
  if (myId < peerId) {
    return 'initiator';
  }
  return 'acceptor';
}

_shouldSendMessageToPeer(peerId) {
  const state = this._getPeerState(peerId);
  if (!state.sessionEstablished || !state.peerRegistered) {
    return false;
  }
  const myRole = this._getConnectionRole(peerId);
  if (myRole === 'initiator') {
    return state.linkReady;
  }
  return true;
}
```

**Change 1b: Fix sendMessage() to use sequential sends (replace lines 645-681)**

```javascript
const readyPeers = [];
for (const [peerId, peer] of this.peers.entries()) {
  const state = this._getPeerState(peerId);
  if (this._shouldSendMessageToPeer(peerId)) {
    readyPeers.push(peerId);
  } else {
    this._logPeerEvent('TX_GATED', { 
      peerId, 
      reason: 'session_not_ready',
      sessionEstablished: state.sessionEstablished,
      peerRegistered: state.peerRegistered,
      linkReady: state.linkReady,
    });
  }
}

if (readyPeers.length === 0) {
  this.enqueueMessage(payload);
  console.log('[MESH] No ready peers, queuing message:', messageId);
  return { id: messageId, queued: true };
}

// Sequential sends to avoid BLE concurrent write errors
for (const peerId of readyPeers) {
  try {
    await this.protocol.sendMessage({ recipient: peerId, content, priority });
    this._logPeerEvent('MESSAGE_DELIVERED', { peerId, messageId, recipientCount: readyPeers.length });
  } catch (e) {
    console.warn('[MESH] send to', peerId, 'failed:', e?.message || e);
  }
  await new Promise(resolve => setTimeout(resolve, 50));
}
return { id: messageId, recipients: readyPeers.length };
```

**Change 1c: Await session establishment (line 310)**

```javascript
// Change from:
this._establishSessionForPeer(peerId);

// To:
await this._establishSessionForPeer(peerId);
```

### Fix 4: Permissions - Ensure Background Location is Requested

**File:** `src/utils/permissions.js`

**Change 4: Add background location permission for Android 10+ (lines 54-68)**

```javascript
const requestAndroidBluetoothPermissions = async () => {
  const required = [
    PermissionsAndroid.PERMISSIONS.BLUETOOTH_SCAN,
    PermissionsAndroid.PERMISSIONS.BLUETOOTH_CONNECT,
    PermissionsAndroid.PERMISSIONS.BLUETOOTH_ADVERTISE,
    PermissionsAndroid.PERMISSIONS.ACCESS_FINE_LOCATION,
  ];

  // Add background location for Android 10+ (needed for BLE scan in background)
  if (Platform.Version >= 29) {
    required.push(PermissionsAndroid.PERMISSIONS.ACCESS_BACKGROUND_LOCATION);
  }

  const result = await PermissionsAndroid.requestMultiple(required);
  const denied = Object.entries(result)
    .filter(([, status]) => status !== PermissionsAndroid.RESULTS.GRANTED)
    .map(([perm]) => perm);

  return { granted: denied.length === 0, denied };
};
```

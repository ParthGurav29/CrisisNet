- `modelStorage.js` has hardcoded URL to wrong model
- No file size verification
- No deleteModel or getModelSize functions
- Wrong model URL (gemma-2b-it instead of gemma-4-E2B-it)

### Changes Required

#### 1. Rewrite `src/utils/modelStorage.js`
```javascript
const MODEL_PATH = `${RNFS.DocumentDirectoryPath}/models/crisisnet-gemma.gguf`;
const MODEL_DIR = `${RNFS.DocumentDirectoryPath}/models`;
```

#### 2. Update `src/ai/gemma.js`

## ISSUE 3: BLUETOOTH MESH UI AND BACKEND VERIFICATION

### Current State
- `meshService.js`: Missing some event logs, event names inconsistent
- `MeshContext.jsx`: Has stale closure risk, missing peer_lost listener
- `Home.jsx`: Missing proper mesh status display, no Bluetooth check
- `Chat.jsx`: Missing empty state
- `MeshStatus.jsx`: No animation, missing color coding for states
- No Bluetooth enable prompt on app launch

### Changes Required

#### 1. Fix `src/mesh/meshService.js`
- Add console.log to ALL events:
  - `neighbor_discovered` → console.log('[MESH] neighbor_discovered:', peer)
  - `neighbor_lost` → console.log('[MESH] neighbor_lost:', peer)
  - `message_received` → console.log('[MESH] message_received:', message)
  - `started` → console.log('[MESH] started')
  - `stopped` → console.log('[MESH] stopped')
- Ensure events are emitted to React layer correctly

#### 2. Fix `src/context/MeshContext.jsx`
- Add listener for `peer_lost` event
- Fix stale closures in event listeners (move handlers outside useEffect or use useCallback)
- Ensure cleanup removes all listeners properly

#### 3. Update `src/screens/Home.jsx`
- Mesh status indicator: ACTIVE (green) or SEARCHING (yellow)
- Show node count: "X devices nearby"
- Show last message timestamp
- If 0 nodes: "No devices found — searching..."
- If 1+ nodes: "X device(s) connected via mesh"
- Bluetooth status: if BLE off, show "Bluetooth is off — mesh disabled" with "Enable Bluetooth" button

#### 4. Update `src/screens/Chat.jsx`
- Show real messages from MeshContext
- Empty state: "No messages yet — mesh is listening"
- Each message shows: sender ID, timestamp, content
- Input and send button connected to meshService.sendMessage
- Sent messages appear immediately
- Received messages appear automatically

#### 5. Update `src/components/MeshStatus.jsx`
- Animated pulse when mesh is active
- Show node count
- Color coded:
  - green = connected
  - yellow = searching
  - red = off

#### 6. Add Bluetooth enable prompt
- After SplashScreen, check if Bluetooth is enabled
- If disabled: Alert "CrisisNet needs Bluetooth for mesh communication. Enable Bluetooth now?"
- Button: "Enable" → opens Android Bluetooth settings

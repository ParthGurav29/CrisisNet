# CrisisNet Critical Bug Fix Plan

## Summary
Fix 4 critical bugs to produce a stable APK:
1. **BUG 1**: MESH SEND CRASH - sendMessage called with wrong parameter format
2. **BUG 2**: MODEL LOAD FAILS - onProgress callback issue in AIContext
3. **BUG 3**: MESH LISTENER CRASH - handlers not defined before registration
4. **BUG 4**: MISSING KEY PROPS - KnowledgeBaseScreen list items need unique keys

---

## Bug 1: MESH SEND CRASH (CRITICAL) ✅ FIXED

**File**: `src/mesh/meshService.js:81-93`

**Problem**: `sendMessage` is called with positional arguments `(recipient, content)` but the SDK expects an object `{ recipient, content, priority }`.

**SDK Analysis** (`node_modules/@offline-protocol/mesh-sdk/lib/index.js:373-377`):
```javascript
async sendMessage(params) {
    const priority = params.priority ?? types_1.MessagePriority.Medium;
    const messageId = await OfflineProtocolNativeModule.sendMessage(params.recipient, params.content, priority, params.replyToMsg ?? null);
    return messageId;
}
```

**Fix Applied**: Changed from:
```javascript
const result = await this.protocol.sendMessage('broadcast', content);
```
To:
```javascript
const result = await this.protocol.sendMessage({ recipient: 'broadcast', content });
```

## Bug 2: MODEL LOAD FAILS (CRITICAL) ✅ FIXED

**Files**: `src/screens/SplashScreen.jsx`

**Problem**: In `SplashScreen.jsx:18`, `loadModel(progress)` was called with an object instead of a function:
```javascript
loadModel(progress);  // WRONG - passing object
```

**Fix Applied**: Changed to:
```javascript
const [progress, setProgress] = useState({ stage: 'Starting...', percent: 0 });
loadModel((progress) => setProgress(progress));  // CORRECT - passing function
```

Also fixed:
- Line 10: Added local `progress` state
- Line 18: Pass function callback instead of object
- Line 39: Use `progressValue` for progress bar
- Line 55: Use `progressValue` for percentage text

## Bug 3: MESH LISTENER CRASH (CRITICAL) ✅ FIXED

**File**: `src/context/MeshContext.jsx`

**Problem**: Event listeners were registered in `useEffect` at lines 54-62, but handlers (`handlePeerDiscovered`, `handlePeerLost`, etc.) were defined AFTER the `useEffect` (lines 74-157). When the effect ran, these handlers were `undefined`.

**Fix Applied**: Moved all handler definitions (`handlePeerDiscovered`, `handlePeerLost`, `handleMessageReceived`, `handleStarted`, `handleStopped`) to be BEFORE the first `useEffect` that uses them. Also added proper dependency array to the second `useEffect`.

**File**: `src/screens/KnowledgeBaseScreen.jsx:120-125`

# CrisisNet Model Loading Fix Plan

## Summary
Fix the model loading in CrisisNet that fails with "Failed to load model".

## Package API Found

**Package:** `llama.rn` v0.12.0-rc.9

**Exact import used:**
```js
import { initLlama } from 'llama.rn';
```

**Exact load function:** `initLlama(params, onProgress?)`

**Parameters:**
- `model`: string (path to GGUF model, must start with `file://` or be a plain path)
- `n_ctx`: number (context size, default 512)
- `n_threads`: number (CPU threads)
- `n_gpu_layers`: number (GPU layers, 0 for CPU-only)
- `use_mmap`: boolean
- `use_mlock`: boolean
- `onProgress`: optional callback `(progress: number) => void`

**Return value:** `Promise<LlamaContext>` - has `completion()` method for inference

**Gemma 4 supported:** NO - Gemma 4 not listed in supported models

**Switched to Gemma 2:** YES - `unsloth/gemma-2-2b-it-GGUF` (already configured in modelStorage.js)
